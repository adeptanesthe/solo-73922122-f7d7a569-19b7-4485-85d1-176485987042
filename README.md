# 剪辑接缝跳听台（Clip Lab）

给剪辑师在**长访谈 PCM 一落盘就进工程页删停顿**的网页工具。Flask + NumPy 实现，
上传单声道 PCM16 WAV，按 **4096 样点**分块；低通摘要改为**后台逐块生成**，
剪辑与跳听不等待全部摘要。撤下/恢复任一块立即更新成片时码；跳听时目标块之前
仍保留的块必须备齐摘要，目标块直接读 PCM；缺摘要就提示“准备中/准备失败”并收起
播放器。

## 它解决什么问题

剪完之后，低通滤波必须作用在“保留样点拼接后的序列”上，而不是在原时间轴上
滤波后再删块（两种结果不同）。本工具把每块对一阶低通的作用预先做成摘要，
撤块时只改摘要，跳听时用摘要恢复滤波器状态，再只读命中块的原始样点。与上一版
相比，摘要不再在上传时一次性算完，而是由后台守护线程逐块准备，PCM 落盘后工程
立即可剪。

### 三个结构，三个 O(log N)

一阶低通 `y[n] = a·y[n−1] + (1−a)·x[n]`（零状态起步，全程 float64 不取整）
对一块长度 L 的样点，等价于关于入块状态的仿射变换：

```
y_out = w·y_in + b,  w = a^L,  b = (1−a)·Σ a^(L−1−n)·x[n]
```

| 结构 | 存什么 | 用途 |
|---|---|---|
| Fenwick 计数树 A | 每块保留样点数（撤下=0） | 成片样点号 → 原块/块内偏移（前缀和 + 第 k 个位置） |
| Fenwick 计数树 B（阻塞树） | 每块“保留且摘要未就绪”的样点数 | O(log N) 找到目标块之前最早的阻塞块 |
| 仿射线段树 | 仅**就绪且保留**块的 (w,b)，其余叶子恒等 (1,0) | 前缀复合得到“进入某块前”的滤波器状态 |

每块两个独立状态：`active`（保留/撤下，剪辑师随时切换）与摘要状态
`pending → ready / failed`。

### 后台逐块准备

- 上传路由只解析 WAV、把裸 PCM 写盘，然后构造工程：构造函数只按总样点数推算
  分块元数据并建三棵树，**不读任何 PCM**，随即 302 进工程页。
- 每个工程一个守护线程 :class:`SummaryWorker`，从队首按块号取任务；读块与
  计算都在**工程锁外**执行，只在发布结果时短暂持锁。因此某块读盘/计算卡住时，
  剪辑与已就绪位置的跳听完全不受影响。
- 单块读盘或计算抛异常只把该块标记 `failed`（带原因），队列其余块继续。
  失败块仍计入阻塞树；撤下它即解除对后续跳听的阻塞。工程页对失败块提供“重试”
  （`POST /api/p/<pid>/chunks/<i>/retry`，重新排到队首）。
- 摘要在块撤下期间算好：只记录、不挂线段树叶子；等恢复时才挂回参与滤波。
- 环境变量 `CLIP_SUMMARY_DELAY`（秒）给每块准备之间加延迟，便于演示
  “边准备边剪”；生产置 0。compose 默认 0.15 s。

### 跳听语义（HTTP 409 阻塞）

1. Fenwick A 定位成片样点 k →（原块, 块内偏移），O(log N)；
2. 查阻塞树：目标块之前（含目标块自身）若有“保留且未就绪”的块，返回
   **409** 与阻塞块号/状态（pending 或 failed），前端红条提示并收起播放器，
   **不读 PCM**；
3. 否则仿射线段树前缀查询拿到入块状态（O(log N) 摘要），**只读 1 个目标块**
   逐样点递推到块末，量化输出 PCM16 WAV。

- **撤下/恢复**：三棵树各 O(log N) 个节点，原始 PCM 读取 0 次（页面实时显示
  这两个计数）。
- **每次跳听请求最多读一次目标块**；JSON 元数据接口与 WAV 接口各自独立、各读
  一次，互相不共享状态。

## 目录

```
app/engine.py      Fenwick 树 ×2、仿射线段树、Project、SummaryWorker（后台线程）
app/wavio.py       单声道 PCM16 WAV 校验与打包
app/main.py        Flask 路由（上传、撤/恢复、重试、状态轮询、跳听 JSON/WAV）
app/templates/     上传页、工程页（状态色块网格 + 轮询 + 时码输入 + 音频播放器）
tools/make_sample_wav.py   生成示例录音
sample_audio/interview_demo.wav  16 kHz、40 块、含 7 个整块停顿的示例录音
tests/test_core.py 引擎核对（含后台失败/卡顿隔离、量化误差、访问计数）
tests/test_web.py  Flask 路由集成测试（可控 worker 注入 + 真实线程并发）
tests/e2e_http.py  针对运行中服务的真实 HTTP 端到端核对（含慢准备 409）
```

## 启动（Docker Compose）

```bash
docker compose up --build
# 浏览器打开 http://localhost:5000
```

容器单 gunicorn worker + 多线程（工程状态在进程内存，多 worker 会互不可见），
上传的裸 PCM 落在命名卷 `clip-data`（容器内 `/data`）。compose 默认开启
`CLIP_SUMMARY_DELAY=0.15`，40 块大约 6 秒备完，方便看到逐块变绿的过程。

不用 Docker 的本地跑法：

```bash
pip install -r requirements.txt
python tools/make_sample_wav.py sample_audio/interview_demo.wav   # 已附带可跳过
CLIP_SUMMARY_DELAY=0.15 flask --app app.main run                  # 想看慢准备就加变量
```

## 边准备边剪的演示步骤

1. 首页选 `sample_audio/interview_demo.wav`，填系数 a（0 ≤ a < 1，如 0.9），
   上传后**立即**跳到工程页，无需等待。
2. 工程页顶部显示“就绪 x / 40，准备中 y，失败 z”，网格里黄色=准备中、
   绿色=就绪、紫色=准备失败、红色描边=已撤下；页面每 0.7 秒轮询状态自动变色。
3. 趁摘要还在准备，直接点 #3、#4、#9、#16、#17、#25、#32 等停顿块撤下：
   成片保留样点数与输入框有效范围**立刻**变化，下方统计显示本次摘要访问数
   （对数级）与原始块读取 0。
4. 在“成片时码跳听”输入样点号：
   - 目标位置之前还有黄/紫块时，返回 409：红条提示“块 #i 摘要仍在准备中/
     准备失败”，播放器自动收起；准备中只需等待轮询变绿后重试；
   - 紫色失败块可直接点它（或调重试接口）重新排队；也可以撤下它立刻解除阻塞；
   - 前置块全部就绪后，定位返回原块号/偏移/试听时长，播放器加载从该样点到
     块末的滤波 PCM16 WAV，统计显示摘要访问为对数级、原始块读取恰为 1。
5. 撤下期间才备好摘要的块，恢复时才挂回滤波；恢复操作同样不读 PCM。

## 验证结果

在 Python 3.11 + NumPy 2.4 + Flask 3.1 下执行（命令均在仓库根目录）：

```bash
PYTHONPATH=. python tests/test_core.py     # 引擎，全部通过
PYTHONPATH=. python tests/test_web.py      # Flask 路由，全部通过
CLIP_DATA_DIR=/tmp/clip-lab-final CLIP_SUMMARY_DELAY=0.05 \
  ~/.local/bin/gunicorn --workers 1 --threads 8 --bind 127.0.0.1:5066 app.main:app &
PYTHONPATH=. python tests/e2e_http.py http://127.0.0.1:5066   # 真实 HTTP，全部通过
```

关键核对点：

- **建工程零读取**：上传后 40 块全部 `pending`，工程对象的 PCM 读取计数为 0；
  无摘要时跳听 409 且不产生 PCM 读取，撤块仍即时更新成片时码。
- **失败隔离**：向 worker 注入块 #2 读盘异常，该块标 `failed` 并带原因，其余
  块全部就绪；撤下 #2 后跳听落到后续块（200），重试（换正常钩子）后恢复就绪。
- **卡顿不阻塞**：分别在读盘钩子和计算钩子里注入 `Event` 阻塞，worker 卡住
  期间已就绪块的跳听成功（每次读 1 个目标块）、撤/恢复即时生效且不读 PCM、
  未就绪位置稳定 409；解除阻塞后 worker 正常退出。
- **撤下期间备好的摘要不参与滤波**：撤下块就绪时线段树叶子保持恒等，恢复后
  才换成真实摘要（测试直接比对叶子值）。
- **量化误差**：随机录音、a ∈ {0, 0.3, 0.85, 0.99}、随机撤块（含非整块结尾），
  对每个保留块块首与块内随机偏移跳听，与“先拼接保留样点、零状态顺序滤波、
  最后统一量化”的参考实现逐样点比对，最大差 0（要求 ≤ 1 个 PCM16 量化单位）。
  两条路径都是 float64 递推、仅输出时 `rint` 量化，公式完全相同。
- **访问复杂度**：N=16/64/256 块实测——撤下/恢复的原始块读取恒为 0、摘要
  访问 9/13/17 个；跳听原始块读取恒为 1、摘要访问 12/14/16 个，N 翻 4 倍时
  访问量增长约 1.1 倍（对数级）。HTTP 端到端 40 块工程单次操作摘要访问 ≤ 20。
- **时码**：枚举全部成片样点号核对定位；越界与非整数输入均 400 并提示重选。
- **格式**：非 WAV、立体声、非 16 位、a 越界/非数字全部拒绝；试听 WAV 为
  单声道 PCM16、同采样率、帧数等于“到块末”样点数。

## 约定与边界

- 上传上限 128 MiB；仅接受单声道、16-bit PCM WAV。
- 工程保存在服务进程内存（重启失效），原始 PCM 落盘在 `/data`；进程退出时
  通过 `atexit` 通知后台线程停止。
- 末块不足 4096 样点时按实际长度处理，三棵树自然兼容。
- a=0 时滤波器退化为直通，已专项测试。
- 后台线程按块号顺序准备；重试任务插到队首。没有做优先级调度（如按剪辑师
  当前关注位置优先）。

## 余下工作

- 本环境没有 Docker 守护进程，**镜像未在此处实际构建/运行**；Dockerfile 与
  compose 已按 gunicorn 单 worker 写好，并已用同版本 gunicorn 在本地以相同
  启动参数跑通全部 HTTP 端到端核对，仍需在有 Docker 的机器上
  `docker compose up --build` 复核一次。
- 工程状态未持久化到磁盘/数据库，服务重启需重新上传；多副本部署需要外置存储。
- 失败重试只提供手动触发与单任务队首优先，没有指数退避/自动重试上限。
- 试听固定输出“到块末”，没有跨块连续试听与波形可视化。
- 大文件上传只有 128 MiB 大小限制，没有分片上传和进度展示。
